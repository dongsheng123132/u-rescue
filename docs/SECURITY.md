# 安全与隐私

这个仓库会被人拿去在自己机器上跑，也可能被 AI 拿去照着执行。
所以它的攻击面不是「代码有没有漏洞」，而是「一份被篡改的病例能造成多大破坏」。

## 边界：病例数据永远不是可执行内容

病例 JSON 里能写的探针只有白名单里那几种（`os_is` / `env_present` / `file_exists` /
`path_has` / `env_contains` / `env_nonascii` / `path_duplicates` / `npm_prefix_on_path` /
`cmd_ok` / `http_reach`），实现在 [`lib/probes.mjs`](../lib/probes.mjs)。

- `cmd_ok` 的可执行名**必须命中 `SAFE_BINS`**，参数只允许 `[A-Za-z0-9._\-=:/@]`。
- 没有任何一种探针接受「一段命令字符串」然后交给 shell。
- `fix.steps[].cmd` 是**给人看的**。CLI 只把它打印出来，从不执行。

结论：就算这个仓库被投毒、或者分发链被中间人篡改，最坏结果是**给出一条误导性建议**，
而不是任意命令执行。这条边界比「多支持几种自动修复」重要得多，别为了方便破掉它。

## 默认只读

- `u-rescue doctor` 不改配置、不装东西。
- **`doctor` 默认连网络都不发**：`http_reach` 探针要显式 `--net`，病例库也不自动拉。
  理由是场景本身——机器坏掉时网络可能就是病因，在那儿卡住会把唯一能用的工具也毁掉。
- 没有遥测，没有上报，不收集任何东西。你跑完就完了，我们不知道。

## 远程更新的边界

`u-rescue update` / `search` 的自动刷新会从网上拉病例库。这条链只拉**数据**，
并且拉回来的每一条都要重新过一遍安全校验（`lib/remote.mjs` 的 `verifyPayload`）：

- 探针 `kind` 必须在白名单里
- `cmd_ok` 的可执行名必须命中 `SAFE_BINS`，参数必须匹配 `[A-Za-z0-9._\-=:/@]`
- **任何一条不合规就整包拒绝**，继续用内置的 —— 部分接受意味着攻击者只要混进一条就得手

缓存写在 `~/.u-rescue/cases-cache.json`，读缓存时也会再校一次（防手改）。
硬超时 4 秒，失败静默降级，绝不抛错、绝不阻断。

仍然不做的：**客户端静默拉取并执行远程规则**。拉的是病例文本，
`fix.steps[].cmd` 从头到尾只被打印，从不进 shell。

## 脱敏

[`lib/redact.mjs`](../lib/redact.mjs) 会在**任何输出之前**处理：API key（多家前缀）、
Bearer token、`key=`/`secret=`/`password=` 形式的赋值、URL 里的 token 参数、
用户名路径（`C:\Users\xxx`、`/home/xxx`、`/Users/xxx`）、邮箱、手机号、内网 IP、UUID。

所以 `npx u-rescue doctor --json` 的输出可以直接贴到 issue 里。
冒烟测试里有一条专门守着这个，改脱敏规则会被测到。

如果你发现有什么该脱没脱的，这算安全问题，请直接开 issue 说明（把真实值换成示例值）。

## 修复步骤的风险声明

每个会改机器的步骤都必须声明 `risk` 和 `rollback`，这是 CI 强制的。
风险分四档：`read-only`（不改）/ `low` / `medium` / `high`。

给 AI 用的 skill 里明确写了：非只读步骤**必须先征得用户同意**再执行。
我们没法强制别人的 AI 遵守，但至少把边界写在了它读到的那份文档里。

## 我们不做的事

- 不写「关掉 TLS 校验」「关掉杀毒软件然后不管」这类把安全性换便利的方案。
  真要临时关，病例里会写明「装完立刻打开」。
- 不收录需要关闭系统安全开关才能生效的自动修复。
- 不把未经脱敏的用户日志变成公开病例。
- 不做客户端静默拉取并执行远程规则。病例更新走 git，你能看到每一次改了什么。

## 报告安全问题

开 issue 即可 —— 这个项目没有需要保密的服务端，也不处理任何用户数据，
不存在需要私下协调披露的场景。
